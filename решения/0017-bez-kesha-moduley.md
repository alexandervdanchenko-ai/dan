# 0017. Без кэша объектных файлов модулей библиотеки

Дата: 2026-11-12

## Контекст

Сторонний разбор 11.11.2026 предложил кэшировать объектные файлы модулей библиотеки (`json`, `excel`, `http` и других), как уже кэшируется среда выполнения из `sreda/` (готовая среда). Предложение принято как кандидат с условием: только если замер покажет выигрыш.

Замер (`замеры/результаты.md`, раздел «Сборка программ с модулями библиотеки»): программа без модулей собирается за 0,075 с, с одним модулем - за 0,35-0,41 с, с модулем `нейро` - за 0,65 с; перевод в C - 0,002-0,04 с (у `нейро` 0,2 с), остальное - компилятор C на коде модуля. Кэш объектных файлов сберёг бы около 0,3 с на сборку с одним модулем. Повторная сборка той же программы уже берётся из кэша исполняемых файлов.

## Решение

Кэш объектных файлов модулей не делается. Программа по-прежнему переводится в одну единицу компиляции C.

## Альтернативы

Отдельная единица компиляции на модуль с кэшем: функции модулей перестают быть `static`, типы и обобщённые функции, которые модуль получает от программы, приходится выносить в общие заголовки и порождать один раз на всю программу, а компилятор C теряет встраивание через границу модуля. Это недели работы ради 0,3 с на первой сборке, с риском для скорости программ. Порождать код модуля только для используемых функций: тоже уменьшает время, но требует анализа достижимости через обобщённые функции; это отдельная задача ускорения сборки.

## Когда пересмотреть

Если типичная программа с модулями собирается дольше 1 с на машинах GitHub, если сервер языка или `dan тестировать` начнут собирать программы на каждое изменение, или если модуль библиотеки вырастет так, что его код C компилируется дольше 1 с.
