# Инструкция для агентов

Этот файл для программ-агентов (Claude Code, Codex и подобных), которые работают в репозитории Дана. Человеку подробнее - в `УЧАСТИЕ.md`.

## Если нужно написать программу на Дане

Прочитайте `llms-full.txt`: в нём правила, которые чаще всего нарушают, вся запись языка, таблица «Python - Дан», все встроенные функции и модули, образцы. Полное описание - `spec.md`. Цикл работы:

```
python dan.py проверить программа.dan          # все ошибки сразу; --json - для программ
python dan.py исправить программа.dan          # применить готовые исправления из сообщений
python dan.py запустить программа.dan          # собрать и выполнить
python dan.py тестировать программа.dan        # блоки тест "..." { }
```

В установленном Дане вместо `python dan.py` пишется `dan`.

## Как устроен компилятор

Два компилятора дают одинаковый результат:

- **На Python** (нулевая ступень): `lexer.py` (слова и знаки) -> `parser.py` (дерево, узлы в `uzly.py`) -> `moduli.py` (подключённые файлы) -> `proverka.py` (типы и смысл, тексты ошибок) -> `kodogen.py` (код C и среда выполнения). Точка входа всех команд - `dan.py`. Встроенные функции - таблицы в `matematika.py`, `vysshaya.py`, `dannye.py`, `sistema.py`, их код на C - в `sreda/`.
- **На Дане** (папка `сам`): `лексер.dan`, `разбор.dan`, `модули.dan`, `проверка.dan`, `порождение.dan`, команды - `дан.dan`. Он обязан давать побайтно то же, что компилятор на Python: те же токены, дерево, тексты ошибок, код C, вывод команд. Это проверяет `test_sam.py`.
- `сам/встроенные.dan` и `сам/среда.dan` создаются сценариями `сам/создать_встроенные.py` и `сам/создать_среду.py` из таблиц Python. После изменения таблиц или `sreda/*.c` их нужно пересоздать.
- Сборка (`собрать`, `запустить`): большие библиотеки среды из `sreda/` и математики собираются один раз в объектные файлы кэша (`gotovaya_sreda.py`, на Дане - `сам/готовая_среда.dan`), программа компонуется с ними; `dan си` печатает по-прежнему самодостаточный код. Отключение: `DAN_GOTOVAYA_SREDA=0`.
- Семя `semya/dan.c` - код C компилятора на Дане; из него компилятор собирается без Python (`sh semya/sobrat.sh`, `semya\sobrat.cmd`). После изменения файлов в `сам` семя обновляется: `python пересоздать.py` или без Python `semya/dan запустить semya/obnovit.dan` компилятором, собранным из нового кода (`--проверить` - только сверить); задание CI «Компилятор из семени» требует, чтобы семя не устарело.
- Модули библиотеки на самом Дане - `библиотека/*.dan` (JSON, CSV, XML, Word, Excel, PDF, почта, HTTP, SQLite, окна).

Любое изменение языка, сообщения или порождаемого кода делается в обоих компиляторах сразу.

## Проверки

```
python testy.py --изменения                    # после правки: только связанные тесты, параллельно
python testy.py                                # всё, параллельно по числу ядер
python testy.py test_sam test_kodogen          # выбранные файлы или классы (test_sam.ТестыСамосборки)
python пересоздать.py                          # пересоздать созданные файлы (после изменения таблиц или конфликта)
python sverka_sborok.py 150                    # gcc и clang, -O0/-O2/-O3/-Os дают одно и то же
python fazzing.py --секунд=60                  # разборщики форматов (нужен clang с libFuzzer)
DAN_KOMPILYATOR=сам python testy.py            # тот же набор, но программы переводит компилятор на Дане
```

При `DAN_KOMPILYATOR=сам` (`sam_kompilyator.py`) `dan.перевести`, `dan.собрать` и команды `python dan.py`, которые есть в компиляторе на Дане, выполняет компилятор на Дане; он собирается один раз и хранится в кэше. Тест, который проверяет устройство компилятора на Python (лексер, дерево, типы узлов), помечается `@sam_kompilyator.про_компилятор_на_python` и в этом режиме пропускается; тесты новых возможностей языка пишутся так, чтобы проходить в этом режиме.

Выбор тестов по файлам задаёт `testy_svyazi.py`: добавляя новый файл тестов или новую часть компилятора, допишите правило (тест `test_testy_svyazi.py` следит, чтобы каждый файл тестов выбирался каким-нибудь изменением).

## Как отправлять изменения

Не отправляйте изменения прямо в `main`: в `main` попадает только запрос на слияние, у которого прошла проверка на всех системах (обязательны задания «Тесты» и «Компилятор из семени» на Linux x86-64 и ARM, macOS и Windows, «Тесты на компиляторе на Дане (Linux)», «Установка в Windows по инструкции» и «Поставка для Windows»; «Фаззинг разборщиков» случаен и не обязателен, но его находку нужно разобрать). Работайте в своей ветке и копии (`git worktree add ../dan-моё -b моя-ветка origin/main`), затем:

```
git fetch -q && git rebase -q origin/main      # конфликт в созданных файлах: python пересоздать.py, git add, git rebase --continue
git push -u origin моя-ветка                   # после rebase: git push --force-with-lease
gh pr create --base main --fill
gh pr merge --auto --rebase --delete-branch    # слияние само произойдёт после зелёной проверки
gh pr checks --watch                           # ждать проверки; подробности упавших: gh api repos/<владелец>/dan/check-runs/<id>/annotations
```

Если `gh pr` недоступен (в сессиях, где закрыт GraphQL GitHub), те же действия делает REST:

```
gh api repos/<владелец>/dan/pulls -f title="..." -f head=моя-ветка -f base=main -f body="..."   # создать
gh run list --branch моя-ветка                                     # проверки ветки; gh run view <id> --json jobs
gh api -X PUT repos/<владелец>/dan/pulls/<номер>/merge -f merge_method=rebase                   # слить после зелёной проверки
```

Если `main` ушёл вперёд, перед слиянием - `git rebase origin/main`, `git push --force-with-lease` и новая проверка.

Не запускайте тесты, пока меняете файлы той же копии репозитория: результаты будут случайными. Сборку под Windows можно проверить так: `x86_64-w64-mingw32-gcc -std=c11 -Werror=implicit-function-declaration` на коде из `python dan.py си программа.dan`.

## Правила

- Тексты (сообщения, документация, комментарии) - по-русски. Только дефис `-`, без длинных и средних тире; проверка: `LC_ALL=C.UTF-8 grep -rnP "\x{2013}|\x{2014}" .`.
- Совместимость: папка `совместимость` не меняется никогда; изменение, которое ломает верную программу, - только в новой редакции (`versiya.py`, раздел 16 `spec.md`); функцию сначала объявляют устаревшей.
- Каждое изменение - с тестом. Новая встроенная функция - в `spec.md` и `справочник.md`, запись в `CHANGELOG.md` (раздел «Не выпущено»).
- Код на C в `sreda/` читает недоверенные данные: размеры и смещения проверяются до использования. Для Windows - только стандартный C и `windows.h`.
- Ускорение не отключает проверки Дана (границы, переполнение, ошибки как значения); заявление о скорости - только с записью в `замеры/результаты.md`.
- В языке и его документации нет правовой части.
- После изменения `spec.md`, таблиц встроенных функций или каталога пересоздайте `llms-full.txt`: `python создать_llms.py`.
