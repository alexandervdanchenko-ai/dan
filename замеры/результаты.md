## Скорость сборки

Дата: 30.10.2026. Заранее собранная среда выполнения (`gotovaya_sreda.py`, `сам/готовая_среда.dan`): большие библиотеки среды собираются один раз и хранятся в кэше, программа собирается только из своей части. Время сборки в секундах с ключом `-O2` (как у `dan запустить` и тестов; замерено до перехода `dan собрать` на `-O3`): наименьшее из трёх, без готовой программы в кэше, готовые части среды уже собраны, gcc 13.3. С `-O3` готовые части собираются отдельно (свой отпечаток). Машина общая с другими работами, разброс до 15%.

Матрица на вектор `дроб32` в NEON (задача из прошлого раздела). Порядок сложения прежний, биты те же. |---|---|---|
| AES-NI | 741-969 | 1560 |
| C, постоянное время | 17,5-18,2 | 25,9 |
| Таблица (прежний) | 28,0-29,6 | 55,9 |

Вариант на C в 1,6-2,2 раза медленнее прежнего: S-блок считается схемой из 113 логических действий на битовых плоскостях 64 байтов (4 блока), а перестановка байтов в плоскости и обратно занимает почти столько же. Он нужен только на процессорах без команд AES (x86-64 до 2010 года и редкие ARM). Команды AES ARMv8 проверены на правильность (qemu и задание CI на ARM), скорость на ARM не замерялась. Повторить: `python -c "import test_dannye as т; т.замер_aes()"` (`DAN_COMPILER=clang` - сборка clang).

## Результат `Т!` без копии

Дата: 08.11.2026. Процессор: Intel(R) Xeon(R) Processor @ 2.10GHz (2 ядра, общая машина), Linux, gcc 13.3, `dan собрать` (`-O3`). Программа: запись с массивом `массив<дроб>` из н чисел (заполнен единицами) и 1000 шагов `д = шаг(д, к)!`, где `шаг` - функция с результатом `Данные!`, которая первой строкой кладёт параметр в свою переменную (`перем д = вход`), меняет один элемент и возвращает запись. «До» - компилятор на Дане из `main` перед изменением (вызов под `!` передавал `д` с учётом второго места, и изменение элемента копировало весь массив), «после» - с переносом значения в вызов под `!` (`сам/порождение.dan`, функция `перенести`). Время - наименьшее из трёх запусков, пик памяти - `ru_maxrss` процесса.

| Массив | До: время, с | До: пик памяти, МБ | После: время, с | После: пик памяти, МБ |
|---|---|---|---|---|
| 10 МБ (1 310 720 чисел) | 1,27 | 21 | 0,01 | 13 |
| 100 МБ (13 107 200 чисел) | 63,8 | 201 | 0,06 | 101 |

После изменения время цикла не зависит от размера массива (0,06 с - заполнение 100 МБ единицами при создании), а в памяти одна копия массива вместо двух. Проверка - `test_rezultat_bez_kopii.py` (код C без `_share` у отданной переменной, пик памяти при массиве 64 МБ меньше 100 МБ, AddressSanitizer на выходе по ошибке).

```

    числа: массив<дроб>
    имя: стр

функ создать(н: цел) -> Данные! {
    перем д = Данные(массив(дроб, н, 1.0), "веса")

    вернуть д
}

функ шаг(вход: Данные, к: цел) -> Данные! {
    перем д = вход
    д.числа[0] = д.числа[0] + дроб(к)
    вернуть д
}

перем д = создать(13_107_200)!
для к в 1..1000 {
    д = шаг(д, к)!
}
вывод(д.числа[0])
```
