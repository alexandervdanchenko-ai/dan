# Принципы языка Дан

Дан задуман как универсальный язык: на нём должна решаться задача любого рода, от расчёта в несколько строк до большой программы с окнами, сетью и базой данных. Второе требование - не повторять известных проблем других языков. Многие из них можно устранить только при создании языка: позднее их исправление ломает уже написанные программы. Поэтому ниже для каждой проблемы записано, какое решение принято в Дане, и в каком оно состоянии.

Обозначения состояния: **есть** - уже работает; **частично** - работает основная часть; **запланировано** - решение принято, реализация впереди.

## 1. Значения и типы

| Проблема других языков | Решение в Дане | Состояние |
|---|---|---|
| Нулевая ссылка (`null`, `nil`, `None`): любое значение может оказаться «пустым», и программа падает при обращении к нему | В Дане нет нулевой ссылки. Переменная всегда получает значение при объявлении. Отсутствие значения выражается отдельным необязательным типом, который компилятор заставляет проверить перед использованием | есть (0.9) |
| Неявные приведения несовместимых типов (`"5" + 1` даёт `"51"` или `6`, `0 == ""` истинно) | Неявно расширяются только числа и списки чисел: `цел` → `рац` → `дроб`, `[цел]` → `[дроб]`. Строку с числом сложить нельзя, преобразование пишется явно: `стр(5)`, `цел("42")` | есть |
| Динамическая типизация: ошибки типов обнаруживаются только при запуске | Статическая типизация: все ошибки типов находятся до запуска, причём выводятся все сразу, а не по одной. Типы выводятся автоматически, указывать их нужно только у параметров функций | есть |
| Размеры чисел зависят от компьютера (`int` бывает 16, 32 или 64 бита) | `цел` - всегда 64 бита, `дроб` - всегда 64-битное число двойной точности | есть |
| Целые числа ограничены, точные дроби отсутствуют | Точные обыкновенные дроби `рац` и многочлены `мн` встроены в язык. Целые числа неограниченной длины - отдельным типом | частично (`рац`, `мн` есть; длинные целые - запланировано) |

## 2. Неопределённое поведение и надёжность

| Проблема других языков | Решение в Дане | Состояние |
|---|---|---|
| Неопределённое поведение (C, C++): результат ошибки зависит от компилятора и может быть любым | У каждого действия определённый результат или определённая ошибка. Неопределённое поведение допустимо только в будущей явно выделенной небезопасной части (вызов функций C) | есть |
| Молчаливое переполнение целых: `9223372036854775807 + 1` даёт отрицательное число | Переполнение всегда останавливает программу с указанием строки. Цена - около 15-20% скорости на чисто арифметических циклах; она сознательно принята, потому что неверное число опаснее задержки | есть (0.8) |
| Выход за границы массива читает чужую память | Каждое обращение по номеру проверяется: `индекс 5 за пределами (длина 3)` | есть |
| Деление на ноль: аварийный сигнал процессора или неопределённость | Целочисленное деление на ноль - ошибка с номером строки; дробное даёт бесконечность, как принято в математике вычислительных машин | есть |
| Отрицательный остаток: `-7 % 3` даёт `-1` | Деление с остатком по школьному определению: остаток всегда от 0 до делителя | есть |
| Переполнение стека при глубокой или бесконечной рекурсии: программа аварийно завершается без сообщения, а уже выведенный текст теряется (C, C++, Go при исчерпании памяти) | Слишком глубокая рекурсия останавливает программу обычной ошибкой выполнения с номером строки функции; выведенное до этого сохраняется. Проверка ставится только в функциях, которые могут вызвать сами себя (прямо или через другие), и стоит до 10% скорости лишь на программах, состоящих из одних вызовов; остальные функции работают без издержек. Так же защищены вывод, сравнение и копирование очень длинных цепочек значений | есть |
| Оператор `goto` и запутанные переходы | Переходов нет; только `если`, `пока`, `для`, `прервать`, `продолжить`, `вернуть` | есть |
| Присваивание внутри условия похоже на сравнение (`if (a = 1)`) | Присваивание - отдельная инструкция, в условии невозможно. На описку `если а = 1` компилятор советует `==` | есть |
| Забытый случай в `switch` (C, Java): новый вид значения добавили, а обработать везде забыли | Перечисления с вариантами и оператор `выбор` с проверкой полноты: если вариант не разобран и нет `иначе`, программа не собирается | есть (0.13) |
| Общие изменяемые данные: изменение объекта в одном месте программы неожиданно меняет его в другом (Java, Python, JavaScript), а функция незаметно меняет переданный ей список | Все значения, включая списки и собственные типы, - значения, а не ссылки: присваивание и передача в функцию не создают общих данных. Копия делается только при изменении значения, хранящегося в нескольких местах, поэтому скорость не страдает. Изменять можно только своё значение в переменной `перем` | есть (0.10) |
| Замыкания видят общую изменяемую переменную: функции, созданные в цикле, неожиданно получают одно и то же последнее значение (JavaScript, Python) | Безымянная функция получает копии внешних переменных в момент создания и не может их изменить | есть (0.13) |

## 3. Память

| Проблема других языков | Решение в Дане | Состояние |
|---|---|---|
| Ручное управление памятью (C, C++): утечки, обращение к освобождённой памяти, около 70% серьёзных уязвимостей в программах на C и C++ | В языке нет указателей и ручного освобождения памяти. Любая ошибка доступа к памяти невозможна по построению | есть |
| Сборщик мусора (Java, C#, Go): паузы в работе программы, повышенный расход памяти | Автоматическое освобождение памяти без сборщика мусора: значение освобождается в тот момент, когда перестаёт быть нужным (подсчёт ссылок, лишние операции с которым компилятор убирает). Паузы исключены, время работы предсказуемо. Поскольку все значения - значения, а не общие ссылки, циклических ссылок, которые подсчёт ссылок не освобождает, в языке нет | есть (0.16); многочлены пока освобождаются при завершении программы |

## 4. Ошибки

| Проблема других языков | Решение в Дане | Состояние |
|---|---|---|
| Исключения (Java, Python, C++): по тексту функции не видно, какие ошибки она может вызвать; пустые обработчики молча скрывают ошибки | Ошибка - обычное значение, возвращаемое функцией. Тип функции показывает, может ли она завершиться ошибкой. Краткий знак передаёт ошибку вызывающему. Не обработать возможную ошибку нельзя: компилятор это обнаружит | есть (0.12) |
| Коды возврата (C, Go): ошибку легко забыть проверить | Возвращённую ошибку нельзя молча проигнорировать | есть (0.12) |
| Сообщения об ошибках на английском, без указания причины и способа исправления | Сообщения на русском, с номером строки и позиции, с тем, что ожидалось и что найдено, и с подсказкой: `возможно, имелось в виду «сумма»`, `для сравнения используйте «==»`. Компилятор показывает все ошибки сразу | есть; каталог ошибок с примерами - запланировано |

## 5. Русский язык в программировании

| Проблема | Решение в Дане | Состояние |
|---|---|---|
| Английские ключевые слова и сообщения - барьер для тех, кто не знает английского | Ключевые слова, типы, библиотека и все сообщения на русском. Ключевые слова короткие и не склоняются: `пусть`, `перем`, `если`, `иначе`, `пока`, `для`, `функ`, `вернуть` | есть |
| Одинаковые на вид русские и латинские буквы (`с` и `c`, `о` и `o`) создают незаметно разные имена | Внутри слова имени смешение алфавитов запрещено, и компилятор называет чужую букву и её место | есть (0.8) |
| `е` и `ё`: одно и то же слово пишут по-разному | В именах `е` и `ё` равнозначны: `счётчик` и `счетчик` - одна переменная | есть (0.8) |
| Невидимые символы направления текста в комментариях и строках показывают на экране не ту программу, которую выполняет компьютер (атака Trojan Source, 2021) | Такие символы запрещены везде; любой невидимый символ в сообщении об ошибке называется кодом и словами | есть |
| Постоянное переключение раскладки ради знаков `*`, `/`, `<=`, `!=` | Школьные знаки: `×`, `·`, `:`, `÷`, `−`, `≤`, `≥`, `≠`, `²`, `³`; слова `и`, `или`, `не` вместо `&&`, `\|\|`, `!` | частично (скобки `{ }` и `[ ]` пока требуют латинской раскладки) |
| Русские буквы в путях к файлам ломаются (особенно в Windows) | Строки всегда в UTF-8, файлы с русскими именами открываются правильно в любой системе | есть |
| Национальные языки замыкаются в своей нише и не могут пользоваться мировыми библиотеками | Вызов функций библиотек, написанных на C, через явно обозначенную границу; это открывает доступ к любой системной и сторонней библиотеке | запланировано |

## 6. Скорость

| Проблема других языков | Решение в Дане | Состояние |
|---|---|---|
| Интерпретация и виртуальные машины (Python, Ruby): медленное выполнение | Компиляция в машинный код через C с полной оптимизацией: программа - самостоятельный исполняемый файл | есть |
| Скрытая цена абстракций: по тексту не видно, где копируются данные или выделяется память | Копирование списков отложено до первого изменения и происходит не больше одного раза на каждое разделение; присваивание и передача в функцию ничего не копируют. Показ мест возможного копирования по ключу компилятора - запланировано | частично |
| Громоздкие исполняемые файлы | Удаление неиспользуемого кода, сборка по размеру (`--малый`) и сжатие (`--сжать`) | есть |
| Заявления о скорости без доказательств | Скорость подтверждается воспроизводимыми замерами с открытой программой замера | запланировано |

## 7. Параллельность

| Проблема других языков | Решение в Дане | Состояние |
|---|---|---|
| Гонки данных: два потока меняют одни данные, ошибка проявляется случайно | Задачи выполняются параллельно и обмениваются данными через каналы; общие изменяемые данные между задачами компилятор не допускает | есть (0.17) |
| Глобальная блокировка интерпретатора (Python): потоки не ускоряют вычисления | Задачи работают на всех ядрах процессора одновременно | запланировано |
| «Окрашивание функций» (`async`): асинхронные и обычные функции несовместимы | Одна модель: любая функция может быть запущена как задача, отдельного вида асинхронных функций нет | есть (0.17) |
| Взаимные блокировки и «забытые» задачи: обмен через каналы сам по себе не избавляет от зависаний (в программах на Go больше половины ошибок, приводящих к зависанию, связаны с каналами) | Задача не переживает блок, в котором создана: блок ждёт завершения всех своих задач. Чтение из закрытого пустого канала даёт определённый результат («ничего»), запись в закрытый канал - ошибка с номером строки. Если все задачи ждут друг друга, программа останавливается с сообщением, где перечислены строки, на которых ждёт каждая задача | есть (0.17) |
| Передача данных между задачами требует сложного анализа владения (Rust) | Значение, отправленное в канал, у получателя своё: списки и собственные типы - значения (раздел 2), поэтому общих изменяемых данных между задачами не возникает без всякого дополнительного анализа | есть (0.17) |

## 8. Развитие языка и экосистема

| Проблема других языков | Решение в Дане | Состояние |
|---|---|---|
| Несовместимые версии (Python 2 и 3): старые программы перестают работать | Каждая программа может указать редакцию языка; компилятор поддерживает все редакции и умеет переводить программу из старой в новую. До версии 1.0 ошибки проектирования исправляются сразу, пока это дёшево | запланировано (до 1.0) |
| Разрастание языка (C++): возможностей больше, чем человек может изучить | Новая возможность добавляется только с письменным обоснованием по порядку из раздела 10 | есть |
| Атаки через пакеты (подменённые и вредоносные библиотеки в npm и других хранилищах) | Менеджер пакетов: опубликованная версия неизменна, точные версии и контрольные суммы всех зависимостей фиксируются, при установке никакой код не выполняется | запланировано |
| Бедная стандартная библиотека заставляет подключать десятки мелких пакетов | Широкая стандартная библиотека: математика, строки, файлы, сжатие, шифрование, архивы уже встроены | частично |
| Сжатые исполняемые файлы вызывают подозрение антивирусов | Сжатие упаковщиком включается только по явному выбору (`--сжать`), по умолчанию файл обычный | есть |

## 9. Что нужно для универсальности

Язык не должен ограничивать круг задач. Ниже - возможности, без которых универсальный язык невозможен, в порядке реализации.

| Этап | Возможности |
|---|---|
| 0.9 | собственные типы (структуры) с полями; необязательные значения вместо `null`; именованные аргументы - **готово** |
| 0.10 | списки как значения с копированием при изменении; сравнение списков - **готово** |
| 0.11 | высшая и прикладная математика в стандартной библиотеке; расширение списков чисел - **готово** |
| 0.12 | словари (ключ - значение); ошибки как значения с обязательной обработкой - **готово** |
| 0.13 | функции как значения, безымянные функции, перечисления с вариантами и сопоставление с образцом - **готово** |
| 0.14 | модули: программа из нескольких файлов, подключение библиотек - **готово** |
| 0.15 | обобщённые функции и типы (одна функция для списков любых значений) с ограничениями: интерфейсы - именованные наборы действий, которые тип обязан уметь выполнять (сравниваться, выводиться, складываться), чтобы обобщённая функция могла их требовать - **готово** |
| 0.16 | автоматическое освобождение памяти без сборщика мусора - **готово** |
| 0.17 | параллельные задачи и каналы - **готово** |
| 0.18 | вызов функций C и системных библиотек; целые числа неограниченной длины; комплексные числа |
| 0.19 | библиотека: дата и время, запуск программ, сеть и HTTP, JSON, регулярные выражения, база данных SQLite |
| 0.20 | окна и графический интерфейс Windows |
| 0.21 | менеджер пакетов, форматирование кода, подсветка и подсказки в редакторе, отладчик |
| 0.22 | вторая цель компиляции - WebAssembly: программы для браузера и для любых систем, где есть исполнитель WebAssembly; проверка сборки и работы в macOS |
| 1.0 | редакции языка, полная спецификация, гарантия совместимости |

Обоснование двух пунктов, добавленных 26.10.2026. Обобщённые функции без интерфейсов не могут потребовать от типа нужных действий: функция «наибольший элемент» должна знать, что элементы можно сравнивать. В Go обобщённые функции с ограничениями появились лишь в 2022 году, через 13 лет после выхода языка, и до этого программисты обходились копированием кода; в Дане эту ошибку проще не повторять, чем исправлять. WebAssembly - единственный, кроме JavaScript, язык, который исполняют все браузеры; без него Дан закрыт для веб-приложений. Поскольку Дан переводится в C, а C компилируется в WebAssembly существующими средствами (clang), эта цель достижима сравнительно дёшево.

## 10. Порядок добавления новых возможностей

Каждая новая возможность записывается в `spec.md` вместе с ответами на вопросы:

1. Какую задачу она решает и почему эту задачу нельзя удобно решить уже имеющимися средствами.
2. Чего она стоит: в скорости, в объёме языка, который нужно изучить, в сложности компилятора.
3. Не повторяет ли она проблему другого языка из разделов 1-8.
4. Не ломает ли она уже написанные программы.

Возможность, которая не прошла эту проверку, не добавляется, даже если она удобна в частном случае.
