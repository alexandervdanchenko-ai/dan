# Оценка языковых моделей

Набор задач с проверками, по которому мерится, насколько верно языковые модели (Claude, GPT, Qwen,
DeepSeek и другие) пишут программы на Дане: с первой попытки и за три попытки, когда модель видит
сообщения компилятора или расхождение вывода. Модель получает описание языка `llms-full.txt` и
условие задачи с примером; итог - доля решённых задач всего и по областям и файл JSON с ответами
модели, программами и сообщениями каждой попытки.

Сейчас в наборе 70 задач (цель - 150):

| Область | Задач | Что проверяется |
|---|---|---|
| `строки` | 8 | разбор строки, символы и срезы, регистр, алфавит с «ё» |
| `числа` | 8 | целое деление и остаток, системы счисления, `длинное`, округление и запись с двумя знаками |
| `рац` | 5 | точные дроби: сумма, перевод из десятичной записи, периодическая и смешанная запись |
| `списки` | 6 | окна, слияние, повороты таблицы, порядок без повторов |
| `словари` | 5 | подсчёт, группировка, упорядочивание по числу и алфавиту |
| `типы` | 6 | записи, перечисления и `выбор`, методы, рекурсивный тип (дерево выражения) |
| `ошибки` | 6 | результаты `Т!` и `Т?`, `ошибка(...)`, коды завершения |
| `файлы` | 4 | аргументы, чтение и запись файлов, папки |
| `json` | 4 | `json.разобрать_в` в свои типы, обход `json.Значение`, запись |
| `csv` | 3 | модуль `csv`: кавычки, разделитель «;» |
| `даты` | 5 | разности, рабочие дни, `добавить_месяцы`, полные годы |
| `параллельность` | 4 | `параллельно для` со сводкой, задачи и каналы |
| `библиотека` | 6 | шаблоны, `xml`, хеши, Base64, римские цифры, сжатие |

Задачи подобраны так, чтобы задевать правила, которые модели нарушают чаще всего (начало
`llms-full.txt`): точное деление `/`, включительные диапазоны и срезы, `Т!` вместо исключений,
отсутствие тернарного оператора и форматных строк, значения вместо ссылок.

## Как запустить против своей модели

Нужен компилятор на Дане: `sh semya/sobrat.sh` (готовый файл `semya/dan`), путь к другому - `--дан=путь`
или переменная `DAN_SAM_EXE`. Сеть нужна только самой модели.

OpenAI-совместимый HTTP API (OpenAI, DeepSeek, Qwen, OpenRouter, vLLM, llama.cpp `llama-server`, Ollama):

```
export OPENAI_BASE_URL=https://api.deepseek.com/v1   # по умолчанию https://api.openai.com/v1
export OPENAI_API_KEY=...                            # ключ в репозиторий не записывается
python оценка_моделей/оценить.py --api --модель=deepseek-chat --температура=0 --потоков=4
```

Модель за командой оболочки: запрос (описание языка, условие, прошлые ответы и сообщения
компилятора) приходит одним текстом на стандартный ввод, ответ читается со стандартного вывода.
Тот же диалог списком сообщений JSON лежит в файле, путь к которому - в переменной среды
`DAN_OCENKA_DIALOG`, имя задачи - в `DAN_OCENKA_ZADACHA`:

```
python оценка_моделей/оценить.py --команда="claude -p" --модель=claude
python оценка_моделей/оценить.py --команда="ollama run qwen2.5-coder" --задачи=1-20
```

Своя функция на Python (`исполнитель(сообщения, задача) -> текст ответа`):

```python
import sys
sys.path.insert(0, "оценка_моделей")
import оценить

def моя_модель(сообщения, задача):
    ...  # сообщения - [{"role": "system" | "user" | "assistant", "content": текст}]
    return ответ

итог = оценить.оценить(оценить.загрузить_задачи(), моя_модель,
                       подсказка=оценить.прочитать_подсказку(оценить.ПОДСКАЗКА))
print(оценить.таблица(итог))
```

Параметры:

| Параметр | Что делает |
|---|---|
| `--эталон` | прогнать эталонные решения вместо модели (так набор проверяется в CI) |
| `--задачи=1,5,10-20,json` | только эти номера, диапазоны или части имён |
| `--области=строки,даты` | только эти области |
| `--попыток=3` | сколько попыток на задачу |
| `--потоков=4` | сколько задач решать одновременно |
| `--подсказка=путь` | описание языка другой версии (по умолчанию `llms-full.txt`); `--подсказка=нет` - без описания |
| `--json=путь` | куда записать подробный итог (по умолчанию `итог_оценки.json`) |

Итог печатается таблицей (числа здесь условные, для примера записи):

```
Область  Задач  С 1-й попытки  За 3 попытки
-------  -----  -------------  ------------
строки       8      6/8 (75%)     7/8 (88%)
...
всего       70   41/70 (59%)   55/70 (79%)
Первые попытки не прошли на этапе: проверка - 21, вывод - 8
Не решены: 036_дерево_выражения, ...
```

Этапы, на которых попытка может не пройти: `ответ` (нет ответа или в нём нет программы), `запись`
(в программе нет конструкции, которую требует условие, например `параллельно для`), `проверка`
(`dan проверить`), `сборка`, `вывод` (вывод, код завершения или файл не те), `время` (дольше 10 секунд).

## Устройство задачи

Задача - два файла в папке `задачи`: `NNN_имя.задача` (условие и проверки) и `NNN_имя.dan`
(эталонное решение, модель его не видит). Файл задачи:

```
область: файлы
трудность: 2
обязательно: канал; запустить

Условие: что программа читает (стандартный ввод, аргументы, файлы в текущей папке) и что печатает.

=== проверка название
=== аргументы
путь.txt
=== файл путь.txt
содержимое файла
=== ввод
строки ввода
=== вывод
ожидаемый вывод
=== код 1
=== файл после отчёт.txt
каким должен стать файл
```

Первая проверка показывается модели примером. Вывод сравнивается построчно, как в задачнике
(`dan задача`): пробелы в конце строк и пустые строки в конце не учитываются. Строка
`\ нет перевода строки` в конце раздела означает, что в конце файла нет перевода строки; файл с
именем на `/` - пустая папка. Каждая программа выполняется в своей папке, созданной для проверки.

Новую задачу проверяет `python оценка_моделей/оценить.py --эталон --задачи=номер`; тест
`test_ocenka_modeley.py` прогоняет все эталоны (компилятором на Дане), проверяет единый вид эталонов
(`dan формат --проверить`) и подсчёт попыток с поддельными исполнителями.
